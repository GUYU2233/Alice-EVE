# 公开仓库与私有运维仓库边界

本项目同时包含可公开分享的应用代码/协议文档，以及仅供授权运维人员使用的部署资料。两类资料必须分开管理，不能因为工作记录、排障或发布说明而互相复制。

## 公开仓库允许的内容

公开仓库可以包含：

- 应用源代码、协议 Schema、API 路径和不含凭据的架构说明；
- 使用文档保留值（例如 `example.invalid`、`203.0.113.10`、`<redacted-zone-id>`）编写的配置示例；
- 不可定位生产环境的测试结果、版本信息和通用部署原则；
- 安全模型、威胁假设、数据最小化和发布流程说明。

公开文档中的示例必须使用占位符或 RFC 5737/RFC 2606 等文档保留值，不能复用生产值。

## 私有运维仓库保留的内容

以下内容只能保留在访问受控的私有运维仓库、密码库或服务器本地：

- 真实公网 IP、可解析的生产域名、主机别名和 DNS 记录；
- Cloudflare Zone ID、账户标识、API 凭据、证书、私钥和 Secret；
- 真实反向代理/CDN/WAF 路由、监听端口、隧道和防火墙细节；
- 服务器绝对路径、systemd 单元、备份位置、日志位置和恢复步骤；
- 生产数据库连接信息、令牌、配置文件和逐主机排障记录；
- 任何可将公开代码直接映射到生产基础设施的组合信息。

私有运维笔记可以引用本仓库的组件路径和接口名称，但公开工作区不得反向复制上述真实值。

## 编辑与审阅规则

1. 提交前对 Markdown、示例配置、脚本注释和发布说明搜索 IP、域名、Zone ID、绝对路径、凭据和内部主机名。
2. 需要展示格式时，替换为 `<production-domain.invalid>`、`<redacted-zone-id>`、`203.0.113.10` 等占位符；不要只遮盖一部分字符串。
3. 公开工作记录只描述“已验证/待验证”的状态和抽象拓扑，不记录可复现生产入口的细节。
4. 服务器配置、DNS、Cloudflare、TLS、防火墙和数据库变更必须在私有运维流程中执行，并在公开文档中仅留下不具定位性的结果。
5. 若敏感值曾经提交到版本库，应按凭据泄露流程轮换/撤销；删除文本本身不能替代轮换。

## 责任边界

公开仓库的维护者负责代码、协议和通用安全要求；私有运维仓库的维护者负责真实环境、凭据、变更审批、备份和事件响应。任何一方都不得把另一方的秘密复制到自己的公开发布物中。
